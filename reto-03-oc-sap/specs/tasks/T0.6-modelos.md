# T0.6 · Modelos de dominio (Pydantic)

## Objetivo
Los tipos del dominio, incluido el payload `OrdenCompra` del PRD §7.4 validado con
Pydantic. Es la pieza que sustituye a `zod` (ADR-001).

## Trazabilidad
| Requisito | Fuente |
|---|---|
| `Paquete` normalizado | PRD §7.2 (textual) |
| `OrdenCompra` validada con esquema | PRD §7.4 (textual) · HU-3 |
| `{apta, bloqueos, confirmaciones, derivados, retroactiva}` | PRD §6.2 · HU-2 |
| `descripcion` máx. 40 caracteres | PRD §7.4 · ADR-004 · I1 |
| `posiciones[].numero` = 10, 20, 30… | I5 |
| `sociedad` y `organizacion_compras` constantes `"1000"` | PRD §7.4 · I4 |
| Sin `Any` | ADR-001 (`mypy --strict`) |

T0.1.

## Modelos exactos

```python
from typing import Literal
from pydantic import BaseModel, Field

Moneda = Literal["COP", "USD"]
Unidad = Literal["UN", "H", "MES"]
TipoVeredicto = Literal["ok", "bloqueo", "confirmacion", "derivado", "no_evaluable"]

# ── Entrada ────────────────────────────────────────────────────────────────

class Solicitud(BaseModel):
    solicitud_id: str
    solicitante: str
    proveedor_nombre: str
    proveedor_nit: str | None = None       # ausente en sol-006
    descripcion: str
    centro_costo: str
    subarea: str
    cantidad: int
    valor_unitario: int
    valor_total: int
    moneda: str
    indicador_iva: str | None = None       # ausente en sol-006 → RC6
    condiciones_pago: str | None = None    # ausente en sol-006 → RC7
    fecha_solicitud: str                   # YYYY-MM-DD

class Correo(BaseModel):
    id: str
    de: str
    asunto: str
    fecha: str

class Cotizacion(BaseModel):
    referencia: str | None                 # ej. "COT-TS-2026-0451"
    proveedor: str
    nit: str | None
    total: int
    moneda: str
    validez_hasta: str | None
    item: str | None                       # nombre del ítem, para inferir_unidad
    texto: str

class Aprobacion(BaseModel):
    de: str
    fecha: str
    aprobado: bool                         # el cuerpo contiene "Aprobado"
    texto: str

class Factura(BaseModel):
    numero: str
    fecha: str
    total: int

class Paquete(BaseModel):
    caso: str
    correo: Correo
    solicitud: Solicitud
    cotizacion: Cotizacion | None
    aprobacion: Aprobacion | None
    factura: Factura | None
    faltantes: list[str] = Field(default_factory=list)   # HU-1: adjuntos ausentes

# ── Maestros ───────────────────────────────────────────────────────────────

class Proveedor(BaseModel):
    codigo_sap: str
    nit: str
    nombre: str
    condiciones_pago_default: str
    indicador_iva_default: str
    activo: bool

class Aprobador(BaseModel):
    email: str
    nombre: str
    tope: int

class CentroCosto(BaseModel):
    centro_costo: str
    nombre: str
    subareas: list[str]
    aprobadores: list[Aprobador]

class IndicadorIva(BaseModel):
    codigo: str
    descripcion: str
    tasa: float

class CondicionPago(BaseModel):
    codigo: str
    descripcion: str
    dias: int

class Maestros(BaseModel):
    proveedores: list[Proveedor]
    centros_costo: list[CentroCosto]
    indicadores_iva: list[IndicadorIva]
    condiciones_pago: list[CondicionPago]

# ── Validación ─────────────────────────────────────────────────────────────

class Veredicto(BaseModel):
    codigo: str                            # "RC1" … "RC10"
    tipo: TipoVeredicto
    detalle: str                           # frase legible para el usuario
    datos: dict[str, str | int | float | bool | None] = Field(default_factory=dict)

class ResultadoValidacion(BaseModel):
    apta: bool
    bloqueos: list[Veredicto] = Field(default_factory=list)
    confirmaciones: list[Veredicto] = Field(default_factory=list)
    derivados: dict[str, str] = Field(default_factory=dict)
    retroactiva: bool = False
    veredictos: list[Veredicto] = Field(default_factory=list)   # los 10, para auditoría

# ── Payload de la OC (PRD §7.4) ────────────────────────────────────────────

class ReferenciaOC(BaseModel):
    solicitud_id: str
    correo_id: str
    cotizacion_ref: str | None

class ProveedorOC(BaseModel):
    codigo_sap: str
    nit: str
    nombre: str

class AprobadorOC(BaseModel):
    email: str
    fecha_aprobacion: str
    evidencia_sha256: str

class PosicionOC(BaseModel):
    numero: int
    descripcion: str = Field(max_length=40)     # límite de texto breve de SAP
    cantidad: int
    unidad: Unidad
    precio_unitario: int
    centro_costo: str
    subarea: str
    indicador_iva: str

class ExcepcionOC(BaseModel):
    codigo: str
    detalle: str
    confirmado_por: str | None                   # session_id (ADR-006)

class OrdenCompra(BaseModel):
    referencia: ReferenciaOC
    sociedad: Literal["1000"] = "1000"
    organizacion_compras: Literal["1000"] = "1000"
    proveedor: ProveedorOC
    moneda: Moneda
    condiciones_pago: str
    aprobador: AprobadorOC
    posiciones: list[PosicionOC] = Field(min_length=1)
    excepciones: list[ExcepcionOC] = Field(default_factory=list)

# ── Resultado uniforme de herramienta (C3) ─────────────────────────────────

def ok(data: object) -> str:
    """Serializa una respuesta exitosa de herramienta: {"ok": true, "data": ...}"""

def error(mensaje: str) -> str:
    """Serializa un fallo de herramienta: {"ok": false, "error": "..."}"""
```

## Comportamiento
- Todos los modelos con `model_config = ConfigDict(extra="forbid")`, **salvo `Correo`
  y `Solicitud`**, que usan `extra="ignore"`.
  - `Correo` lo necesita de verdad: el `correo.json` real trae ocho campos (`id`, `de`,
    `para`, `asunto`, `fecha`, `cuerpo`, `adjuntos`, `nota_fixture`) y el modelo declara
    cuatro, los que llegan al paquete normalizado del PRD §7.2. Con `extra="forbid"`
    el parseo del fixture lanza `ValidationError`. **Es obligatorio un test de `Correo`
    contra los 6 `correo.json` reales.**
  - `Solicitud` lo lleva por precaución: los 6 `solicitud.json` actuales **no** traen
    campos extra, pero el formato de origen es un Excel y es plausible que aparezcan.
- `ok()` y `error()` devuelven **string** con `json.dumps(..., ensure_ascii=False)`.
  Devolver un dict es un defecto: el PRD §6.2 exige string.
- Los montos son `int` (pesos colombianos sin decimales). **No uses `float` para
  dinero**; solo `tasa` de `IndicadorIva` es `float`.
- Las fechas son `str` en `YYYY-MM-DD` o ISO 8601. No convertir a `datetime` aquí:
  la comparación de fechas es asunto de los controles RC8 y RC9.

## Casos de prueba
| Escenario | Esperado |
|---|---|
| `Solicitud` desde `fixtures/.../sol-001/solicitud.json` | valida |
| `Solicitud` desde `sol-006` | valida, con `proveedor_nit`, `indicador_iva` y `condiciones_pago` en `None` |
| `Maestros` cargados desde los 4 JSON reales | 5 proveedores, 3 centros, 3 IVA, 4 condiciones |
| `PosicionOC` con `descripcion` de 41 caracteres | `ValidationError` (I1) |
| `PosicionOC` con `descripcion` de 40 | valida |
| `OrdenCompra` con `posiciones=[]` | `ValidationError` |
| `OrdenCompra` con `moneda="EUR"` | `ValidationError` (I9) |
| `OrdenCompra` sin especificar `sociedad` | queda `"1000"` (I4) |
| `PosicionOC` con `unidad="KG"` | `ValidationError` |
| `ok({"a": 1})` | string `'{"ok": true, "data": {"a": 1}}'`, parseable |
| `error("falló")` | string parseable con `ok=False` y la clave `error` |
| `ok({"x": "Papelería"})` | el string contiene `Papelería` sin escapar (`ensure_ascii=False`) |

Los modelos de entrada deben validarse contra **los 6 fixtures reales**, no contra
diccionarios inventados. Usa `pytest.mark.parametrize` sobre `sol-001`…`sol-006`.

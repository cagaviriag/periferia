# T1.3 · RC10 (aritmética) y RC5 (cotización vs solicitud)

## Objetivo
El control que verifica que la solicitud cuadra consigo misma, y el que la contrasta
con la cotización del proveedor.

## Trazabilidad
| Requisito | Fuente |
|---|---|
| RC10 · `cantidad × valor_unitario == valor_total` (± 1 unidad monetaria) | PRD §7.3 RC10 (**Bloqueo**) |
| RC5 · desviación ≤ 2 %; si excede o no hay cotización → confirmación | PRD §7.3 RC5 (Confirmación) |
| sol-004 confirma por desviación del 6 % | oráculo §sol-004 |
| El PRD §11 exige mostrar **ambos** valores en la UI | PRD §11 |

## Dependencias
Fase 0. No depende de T1.1 (no usa resolutores).

## Firmas exactas

```python
from app.core.modelos import Paquete, Veredicto

UMBRAL_DESVIACION = 0.02   # 2 %, PRD §7.3 RC5
TOLERANCIA_REDONDEO = 1    # ± 1 unidad monetaria, PRD §7.3 RC10

def rc10_aritmetica(paquete: Paquete) -> Veredicto:
    """RC10 · cantidad × valor_unitario debe igualar valor_total. Bloqueo."""

def rc5_cotizacion(paquete: Paquete) -> Veredicto:
    """RC5 · El total de la cotización no puede desviarse más del 2 % del
    valor_total de la solicitud. Confirmación."""
```

Ninguna recibe `Maestros`: estos dos controles solo miran el paquete.

## Comportamiento

### `rc10_aritmetica`
1. `esperado = solicitud.cantidad * solicitud.valor_unitario`.
2. `diferencia = abs(esperado - solicitud.valor_total)`.
3. Si `diferencia <= TOLERANCIA_REDONDEO` → `ok`.
4. Si no → `bloqueo`, con `detalle` que muestre la multiplicación explícita
   (`120 × 95.000 = 11.400.000`, pero la solicitud dice X) para que el error se vea.
5. Caso de borde: `cantidad == 0` → `bloqueo` con detalle propio ("cantidad en cero").

`datos`: `cantidad`, `valor_unitario`, `esperado`, `valor_total`, `diferencia`.

### `rc5_cotizacion`
1. Si `paquete.cotizacion is None` → `confirmacion`: *"no hay cotización para
   contrastar el valor"*. No es bloqueo: el PRD lo clasifica como confirmación.
2. Si `solicitud.valor_total == 0` → `confirmacion` con detalle propio. **No dividas
   por cero.** El PRD no contempla este caso; se trata como imposible de verificar.
3. `desviacion = abs(cotizacion.total - solicitud.valor_total) / solicitud.valor_total`.
4. Si `desviacion <= UMBRAL_DESVIACION` → `ok`.
5. Si excede → `confirmacion`. El `detalle` **debe** traer los dos montos con separador
   de miles, el porcentaje de desviación con dos decimales, y decir explícitamente
   **cuál valor se usará si se confirma: el de la solicitud**, porque es el monto que el
   líder aprobó.

`datos`: `valor_solicitud`, `valor_cotizacion`, `desviacion_pct` (float con 2
decimales), `umbral_pct`.

El punto 5 no es cosmético: el PRD §11 describe que la demo debe mostrar *"lista de
confirmaciones con los dos valores (solicitud vs cotización)"*. Si el `detalle` no los
trae, la UI no puede cumplir.

## Casos de prueba

| Caso | `rc10` | `rc5` | Aritmética |
|---|---|---|---|
| sol-001 | `ok` | `ok` | `120 × 95.000 = 11.400.000` · cot. 11.400.000 → 0,00 % |
| sol-002 | `ok` | `ok` | `5 × 1.700.000 = 8.500.000` · cot. 8.500.000 → 0,00 % |
| sol-003 | `ok` | `ok` | `40 × 1.850.000 = 74.000.000` · cot. 74.000.000 → 0,00 % |
| sol-004 | `ok` | **`confirmacion`** | `100 × 250.000 = 25.000.000` · cot. **26.500.000** → **6,00 %** |
| sol-005 | `ok` | `ok` | `1 × 3.200.000 = 3.200.000` · cot. 3.200.000 → 0,00 % |
| sol-006 | `ok` | `ok` | `30 × 180.000 = 5.400.000` · cot. 5.400.000 → 0,00 % |

**sol-004 es el test central.** Debe afirmar:
- `rc5.tipo == "confirmacion"`
- `rc5.datos["desviacion_pct"] == 6.00`
- el `detalle` contiene ambos montos formateados y menciona que se usará el de la solicitud
- `rc10.tipo == "ok"` — la solicitud cuadra consigo misma; el desacuerdo es con el proveedor

Tests adicionales obligatorios:
- **Sin cotización:** `cotizacion=None` → `confirmacion`, nunca `bloqueo`.
- **Límite exacto del 2 %:** `valor_total=100.000.000`, `cotizacion.total=102.000.000`
  → `ok` (el PRD dice ≤).
- **Un peso sobre el límite:** `cotizacion.total=102.000.001` → `confirmacion`.
- **RC10 con desajuste:** `cantidad=10`, `valor_unitario=100`, `valor_total=5.000`
  → `bloqueo`, y el `detalle` muestra `10 × 100 = 1.000`.
- **RC10 tolerancia de redondeo:** `valor_total = esperado + 1` → `ok`;
  `esperado + 2` → `bloqueo`.
- **`valor_total == 0`:** RC5 → `confirmacion` sin lanzar `ZeroDivisionError`.
  Verifícalo con `pytest.raises` invertido o simplemente llamando.
- **`cantidad == 0`:** RC10 → `bloqueo`.

# T1.4 · RC6 (IVA derivado) y RC7 (condiciones de pago derivadas)

## Objetivo
Los dos controles que completan datos faltantes desde el maestro de proveedores.
**La diferencia entre ellos es lo que se califica:** RC6 exige confirmación, RC7 solo
informa.

## Trazabilidad
| Requisito | Fuente |
|---|---|
| RC6 · `indicador_iva` ausente → derivar del proveedor **+ confirmación** | PRD §7.3 RC6 |
| RC7 · `condiciones_pago` ausente → derivar del proveedor, **solo informa** | PRD §7.3 RC7 |
| `derivados` son valores completados desde maestros y **deben informarse** | PRD §5 HU-2 |
| sol-006 dispara ambos: derivados `C1` y `Z030` | oráculo §sol-006 |
| `indicadores-iva.json` trae `tasa: 0` como entero para `C0` | plan §H6 |

## Firmas exactas

```python
from app.core.modelos import Maestros, Paquete, Veredicto

def rc6_indicador_iva(paquete: Paquete, maestros: Maestros) -> Veredicto:
    """RC6 · Si la solicitud no trae indicador de IVA, se deriva del proveedor
    y se pide confirmación por su impacto fiscal."""

def rc7_condiciones_pago(paquete: Paquete, maestros: Maestros) -> Veredicto:
    """RC7 · Si la solicitud no trae condiciones de pago, se derivan del
    proveedor y solo se informan."""
```

## Comportamiento

### `rc6_indicador_iva`
1. Si `solicitud.indicador_iva` **no** es `None`: validar que el código exista en
   `maestros.indicadores_iva`.
   - Existe → `ok`.
   - No existe → `bloqueo`: un código de impuesto inventado no se puede enviar a SAP.
     El `detalle` lista los códigos válidos.
2. Si es `None`:
   - `proveedor = resolver_proveedor(...)`. Si es `None` → `no_evaluable`, porque sin
     proveedor no hay default del que derivar (RC1 ya habrá bloqueado).
   - Derivar `proveedor.indicador_iva_default`.
   - Validar que ese código exista en el maestro de IVA. Si no → `bloqueo` (el maestro
     de proveedores apunta a un indicador inexistente: es un problema de datos maestros).
   - Devolver `confirmacion`, con `detalle` que diga el código derivado, su descripción
     y su tasa, y de dónde salió (el proveedor). Ejemplo de lo que debe comunicar:
     *"la solicitud no informó indicador de IVA; se tomó C1 (IVA 19%) del maestro del
     proveedor TecnoSuministros S.A.S."*

`datos`: `indicador_iva`, `origen` (`"solicitud"` o `"derivado"`), `tasa`,
`descripcion`.

**Sobre la tasa:** en `indicadores-iva.json` el valor de `C0` es `0` (entero) y Pydantic
lo coacciona a `0.0`. El campo es `float`; no lo compares con `is` ni asumas `int`.

### `rc7_condiciones_pago`
Misma lógica que RC6, **salvo el tipo de veredicto cuando se deriva**:
1. Si viene informada: validar contra `maestros.condiciones_pago` →
   `ok` o `bloqueo` (código inexistente).
2. Si es `None`: derivar `proveedor.condiciones_pago_default`, validar, y devolver
   **`derivado`**, no `confirmacion`.

`datos`: `condiciones_pago`, `origen`, `dias`, `descripcion`.

**Por qué la asimetría con RC6:** el PRD la establece explícitamente. La lectura de
negocio es que el indicador de IVA tiene impacto fiscal y contable que alguien debe
asumir, mientras las condiciones de pago son un acuerdo comercial ya pactado con el
proveedor y registrado en el maestro. Déjalo en un comentario: es lo primero que un
evaluador va a preguntar.

## Casos de prueba

| Caso | `rc6` | `rc7` | Por qué |
|---|---|---|---|
| sol-001 | `ok` | `ok` | trae `C1` y `Z030`, ambos existen |
| sol-002 | `ok` | `ok` | trae `C1` y `Z030` |
| sol-003 | `ok` | `ok` | trae `C1` y `Z030` |
| sol-004 | `ok` | `ok` | trae `C1` y `Z000` |
| sol-005 | `ok` | `ok` | trae `C1` y `Z015` |
| sol-006 | **`confirmacion`** | **`derivado`** | no trae ninguno de los dos |

**sol-006 es el test central.** Debe afirmar:
- `rc6.tipo == "confirmacion"` y `rc6.datos["indicador_iva"] == "C1"`
- `rc7.tipo == "derivado"` — **no** `"confirmacion"`
- `rc7.datos["condiciones_pago"] == "Z030"`
- ambos con `origen == "derivado"`
- los dos valores provienen del proveedor `codigo_sap="100234"`, **leído del fixture**

Tests adicionales obligatorios:
- **Código de IVA inexistente:** `indicador_iva="C9"` → `bloqueo`, y el `detalle` lista
  `C0`, `C1`, `C2`.
- **Código de condiciones inexistente:** `condiciones_pago="Z999"` → `bloqueo`.
- **Proveedor no resoluble:** paquete con NIT inexistente **y** sin `indicador_iva` →
  `rc6.tipo == "no_evaluable"`, no una excepción ni un `bloqueo` duplicado.
- **Tasa de `C0`:** afirmar que `indicador_iva="C0"` da `ok` y que su tasa se lee como
  `0.0` sin error de tipo.
- **Los derivados salen del maestro real:** en lugar de escribir `"C1"` a mano, lee
  `proveedores.json`, busca `codigo_sap="100234"` y compara contra sus campos
  `indicador_iva_default` y `condiciones_pago_default`.
